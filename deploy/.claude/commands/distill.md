# 蒸馏当前对话

你是知识蒸馏器。严格逐步执行，不要跳步。

## 第 0 步：读配置与索引

- 读取 `.claude/distill.config.md`（先项目内后 `~/.claude/`），获取「知识库路径」和「Python命令」；未配置时用 `python`。下文记为 `<Python命令>`。
- 读取 `<知识库路径>/topics/INDEX.md`，了解已有主题；索引不存在时运行：
  ```bash
  <Python命令> "<知识库路径>/deploy/scripts/kb.py" build
  ```

## 第 1 步：拉取最新

在「知识库路径」执行 `git -C "<知识库路径>" pull --rebase --autostash`。
- 非 git 仓库或 pull 失败：停止并告知用户原因。
- 冲突：停止并报告，不要自行解决。

## 第 2 步：提炼卡片

删除寒暄、过程性废话和只对本次有效的内容，只留可复用知识。涉及「怎么做/怎么调」时归纳成通用方法，不写单次数值。

输出字段：

- 【主题】从 `topics/INDEX.md` 选最接近的；都不合适才新建，主题名要短且可复用。
- 【标题】一句话概括这张卡。
- 【类型】流程 / 原则 / 坑 / 决策 / 参考
- 【标签】2~5 个
- 【来源】AI建议 / 实测 / 论文 / 他人经验 / 混合
- 【置信度】高 / 中 / 低
- 【核心知识点】一句话
- 【通用方法/原则】可执行的步骤或原则
- 【适用条件】
- 【失效条件】什么情况下不适用
- 【我的决策】只有对话中明确出现时才写；没有就写「待补充」
- 【证据/结果（案例）】实际参数、结果或案例；没有就写「待补充」

**优先沉淀「我的决策 + 证据」**；纯 AI 通用知识应降低置信度，避免把模型已知内容当成个人经验。

## 第 3 步：写入原子卡片

1. 生成文件名：`cards/<主题>/<YYYY-MM-DD>-<slug>.md`，slug 用英文小写 kebab-case。
2. 卡片内容：

```markdown
---
id: <YYYY-MM-DD>-<slug>
topic: <主题>
title: <标题>
type: <类型>
tags: [<标签1>, <标签2>]
source: <来源>
confidence: <置信度>
created: <YYYY-MM-DD>
review_after: <YYYY-MM-DD，默认 6 个月后>
status: active
last_used:
related: []
---

# <标题>

【核心知识点】...

【通用方法/原则】
- ...

【适用条件】...

【失效条件】...

【我的决策】...

【证据/结果（案例）】...
```

3. 运行校验与脱敏扫描：

```bash
<Python命令> "<知识库路径>/deploy/scripts/kb.py" validate "cards/<主题>/<文件名>.md"
<Python命令> "<知识库路径>/deploy/scripts/kb.py" scan "cards/<主题>/<文件名>.md"
```

- 任一失败：停止并报告，不要提交。
- scan 命中时把命中行报告给用户，等待确认；不要自动删除内容。

4. 重新生成主题页与索引：

```bash
<Python命令> "<知识库路径>/deploy/scripts/kb.py" build --topic "<主题>"
```

## 第 4 步：提交并推送

- 执行 `git -C "<知识库路径>" status --short`，确认本次改动范围。
- 只暂存本次相关文件，禁止 `git add -A`：
  ```bash
  git -C "<知识库路径>" add -- "cards/<主题>/<文件名>.md" "topics/<主题>.md" "topics/INDEX.md"
  ```
- 其他已修改/未跟踪文件保持原样，不纳入本次提交，并在最后报告中说明。
- `git -C "<知识库路径>" commit -m "distill: <主题> - <标题>"`
- 推送前再同步一次：`git -C "<知识库路径>" pull --rebase --autostash`；失败则停止并报告。
- `git -C "<知识库路径>" push`；失败则报告错误，不要强行处理。

## 最后报告

说明：卡片路径、主题、核心知识点、校验/扫描结果、是否推送成功；若有未提交的无关改动也一并说明。
